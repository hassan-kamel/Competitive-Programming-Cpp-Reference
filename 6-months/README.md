## 📊 **Problem-Solving Strategy by Difficulty** ⭐

### **The Smart Strategy: Master Medium Problems!**

> **Reality Check:** 80-90% of interview questions are Medium difficulty. Hard problems have diminishing returns. Focus on solving MORE medium problems with DEEP understanding rather than struggling with fewer hard problems.

### **Month 1-2: Foundation**

- **Easy:** 50% (175-200 problems) - Build confidence & speed
- **Medium:** 45% (160-180 problems) - Core interview patterns
- **Hard:** 5% (15-20 problems) - Optional, only classics
- **Total:** ~350-400 problems
- **Goal:** Speed + Pattern Recognition

### **Month 3-4: Intermediate**

- **Easy:** 20% (70-80 problems) - Quick warm-ups
- **Medium:** 70% (245-280 problems) - **MAIN FOCUS**
- **Hard:** 10% (35-40 problems) - Select important ones
- **Total:** ~350-400 problems
- **Goal:** Deep Pattern Mastery

### **Month 5-6: Advanced**

- **Easy:** 10% (35-40 problems) - Speed practice
- **Medium:** 75% (260-300 problems) - **MAXIMUM FOCUS**
- **Hard:** 15% (55-60 problems) - Company-specific
- **Total:** ~350-400 problems
- **Goal:** Interview Confidence + Speed

### **Why This Works:**

✅ **Medium problems** cover 80%+ of actual interview questions
✅ More problems solved = Better pattern recognition
✅ You can solve 3-4 mediums in the time of 1 hard
✅ Better ROI (Return on Investment) for your time
✅ Builds confidence and interview speed

### **When to Do Hard Problems:**

- Only after mastering medium patterns
- Focus on **classic hards** that teach important concepts
- Company-specific hards (if targeting specific companies)
- Don't spend more than 45-60 min on a hard problem

## 💡 **The Medium-Problem Mastery Framework**

### **How to Solve Medium Problems Effectively:**

**Step 1: Problem Analysis (5 min)**

```
1. What's the input/output?
2. What are the constraints? (size, time limit)
3. What pattern does this match? (sliding window, DP, graph, etc.)
4. What's a brute force solution?
```

**Step 2: Optimize & Code (20-25 min)**

```
1. Can I optimize using a data structure? (hash map, heap, stack)
2. Can I use two pointers, binary search, or greedy?
3. Write clean code with good variable names
4. Add comments for complex logic
```

**Step 3: Test & Review (5-10 min)**

```
1. Test with examples from problem
2. Think of edge cases (empty input, single element, all same)
3. Verify time/space complexity
4. Can this be further optimized?
```

### **When to Look at the Solution:**

❌ **Don't look immediately** - Try for 30-40 minutes first
✅ **Look after 40-45 min** - No shame in learning from solutions
✅ **Study the solution deeply** - Understand WHY it works
✅ **Code it from memory** - Next day, solve again without looking
✅ **Explain it out loud** - If you can teach it, you know it

### **The 3-Review System:**

1. **First solve:** Understand the solution (Day 1)
